Main View

The Main View is a composed view that contains multiple sub-views.

It does NOT communicate with the Controller directly.

Instead, it acts as a bridge between:

  • Sub-views (CalendarView, InputView, DayDetailView)
  • Main Window (which owns the Controller)

Structure

MainView
├── PlanInputView
├── CalendarView
└── DayDetailView

Responsibilities

  • Build layout (UI structure)
  • Bind events from sub-views
  • Forward user interactions upward
  • Render data into sub-views

Data Flow

MainView does NOT talk to Controller.

Downward (Rendering):

MainWindow → MainView.render_xxx() → Sub Views

Upward (Events):

Sub Views → MainView.on_xxx() → MainWindow

Example: Day Selection

CalendarView detects click
→ MainView.on_day_selected(day)

→ MainView forwards event:
   on_day_selected_callback(day)

→ MainWindow handles it

Example: Rendering Calendar

MainWindow gets data from Controller

→ MainView.render_calendar(year, month, workload)

→ CalendarView.refresh(...)
→ CalendarView.set_workload(...)

Key Rule

MainView MUST NOT:
- access controller
- manage application state

MainView MUST:
- render data
- forward events
